# 视频标定矫正说明（macOS）

对应脚本：`Beatbot-tools/spjz/视频标定矫正.py`  
启动方式：双击 `运行视频标定矫正.command`，或：

```bash
cd Beatbot-tools/spjz
python3 视频标定矫正.py
```

依赖：`opencv-python`、`Pillow`、`numpy`；导出 MP4 建议：

```bash
brew install ffmpeg
```

本工具把泳池监控画面做成鸟瞰图（BEV）：先去镜头畸变，再在去畸变图上点选标志、计算单应性，最后导出矫正视频。参数保存为 `bird_eye_params_*.xml` / `.json`。

---

## 1. 原理

监控相机同时存在两类几何误差，必须分开处理：

| 误差 | 来源 | 能消除它的方法 | 单应性能否消除 |
|---|---|---|---|
| 桶形 / 鱼眼弯曲 | 镜头径向畸变 | 相机内参 `K` + 畸变系数 `D` 去畸变 | **不能** |
| 透视倾斜 | 相机不垂直朝下 | 平面单应性 `H` | 能 |

只做透视变换时，池边仍会外鼓。这不是点选不准，而是单应性假设「直线仍是直线」，鱼眼画面不满足这个假设。

### 1.1 去畸变

针孔相机把三维点投到像素：

\[
\begin{bmatrix} u \\ v \\ 1 \end{bmatrix}
\sim
K
\begin{bmatrix} X_c / Z_c \\ Y_c / Z_c \\ 1 \end{bmatrix}
,\quad
K=
\begin{bmatrix} f_x & 0 & c_x \\ 0 & f_y & c_y \\ 0 & 0 & 1 \end{bmatrix}
\]

鱼眼镜头在投影前还有径向畸变。本脚本默认使用 OpenCV `fisheye` 模型，畸变系数为 4 个数 `[k1, k2, k3, k4]`，与 `calib_H.py` 一致。

默认内参（主点约在画面中心）：

- \(c_x \approx 1423.36\)，\(c_y \approx 805.95\)
- 由此反推标定分辨率约 **2847 × 1612**（接近 2880 × 1620）
- 去畸变时 `balance=1`：尽量保留全部视场，四周可能出现黑边

`K` 是在特定分辨率下标定的。视频宽高不同时，必须按比例缩放：

\[
f_x' = f_x \cdot \frac{W}{W_0},\quad
c_x' = c_x \cdot \frac{W}{W_0},\quad
f_y' = f_y \cdot \frac{H}{H_0},\quad
c_y' = c_y \cdot \frac{H}{H_0}
\]

畸变系数 `D` 不随分辨率缩放。脚本默认勾选「按当前画面缩放内参」。

### 1.2 单应性（鸟瞰）

去畸变之后，泳池甲板可近似看成一个平面。平面上的点在「去畸变图像」与「鸟瞰图」之间满足：

\[
\begin{bmatrix} x' \\ y' \\ 1 \end{bmatrix}
\sim
H
\begin{bmatrix} x \\ y \\ 1 \end{bmatrix}
\]

至少 4 对点即可求解 `H`。脚本中：

- 图像点：在**已去畸变**画面上点击棋盘格角点
- 世界点：该标志在场地坐标系中的位置（米）
- 鸟瞰像素：`像素 = 米 × pixel_scale`，再加边距

默认 `pixel_scale = 100` 表示 1 米对应 100 像素。比例过低会把画面缩小，导出视频发糊。

### 1.3 一次 remap（画质）

参考脚本是两步插值：

1. `undistortImage`：原图 → 去畸变图
2. `warpPerspective`：去畸变图 → 鸟瞰图

每一步都会采样一次，细节变糊。本脚本预先合成采样表：

```
鸟瞰像素 (u', v')
    -- H⁻¹ --> 去畸变像素 (u, v)
    -- 去畸变 map --> 原始鱼眼像素 (x, y)
```

导出时对每一帧只做一次 `cv2.remap`。

## 2. 实现

### 2.1 运行与依赖

```text
pip install opencv-python numpy pillow
# 可选：加载 camera_params.yaml
pip install pyyaml
# 可选：更高画质导出（需本机 ffmpeg 带 libx264）
```

```text
python Softwaretest/视频矫正/视频标定矫正.py
```

### 2.2 操作流程

1. **打开视频**（推荐，用第一帧标定）或打开图片。不要用显示器截图，分辨率会和原视频不一致。
2. 去畸变选 `fisheye`，点「应用去畸变」。标题应变为「已去畸变」，池边应明显变直。
3. 若边沿仍外鼓：勾选「按当前画面缩放内参」，或把「内参标定分辨率」改成这套 `K` 的真实标定尺寸（默认 2847×1612），或加载该泳池自己的 `camera_params.yaml`。
4. 在左侧填写标志的真实坐标（米），顺序必须和点击顺序一致。点数 ≥ 4。
5. 在去畸变图上按顺序左键点选；右键撤销。可用放大镜对准棋盘格角点。「显示原始鱼眼」只用于对照，不能在原图上点选。
6. 建议点「按选点自动比例」，再用「计算单应性并预览」。确认鸟瞰图池边平直、长宽比正常。
7. 「保存标定」写出 XML + JSON；「矫正视频并导出」生成鸟瞰视频。

### 2.3 关键代码路径

| 步骤 | 函数 | 作用 |
|---|---|---|
| 缩放内参 | `scale_camera_matrix` | 按当前画面相对标定分辨率缩放 `fx, fy, cx, cy` |
| 生成去畸变表 | `prepare_undistort` | 鱼眼：`estimateNewCameraMatrixForUndistortRectify` + `initUndistortRectifyMap` |
| 预览去畸变 | `remap_undistort` | 标定界面显示已拉直的图 |
| 鸟瞰画布尺寸 | `compute_dst_geometry` | 世界坐标（米）→ 像素，加边距，宽高补成偶数 |
| 估算比例 | `suggest_pixel_scale` | 用选点像素距 / 米距的中位数 |
| 合成采样表 | `build_bev_maps` | `H⁻¹` 再叠上去畸变 map |
| 分辨率不一致 | `scale_homography_for_src` | 标定图与视频尺寸不同时变换 `H`，避免先缩小视频 |
| 导出 | `open_video_writer` / `_rectify_worker` | 英文临时目录写入，再搬到目标路径 |

界面点击坐标会除以显示缩放比，得到去畸变原图像素，不在缩略图上直接算 `H`。

### 2.4 界面参数

| 参数 | 默认 | 含义 |
|---|---|---|
| 去畸变 | `fisheye` | `fisheye` / `standard` / `none`。`none` 时池边会保持弯曲 |
| balance | `1.0` | 与 `calib_H.py` 相同；越小裁得越多，越大黑边越多 |
| 按当前画面缩放内参 | 开 | 视频分辨率 ≠ 2847×1612 时必须开 |
| 内参标定分辨率 | 2847 × 1612 | 这套默认 `K` 的标定尺寸 |
| 比例 px/m | 100 | 鸟瞰图尺度；建议用「按选点自动比例」 |
| 边距 X/Y (m) | 0.5 / 0.5 | 鸟瞰图四周留白 |

预设点：

- **矩形 4 点**：按输入长宽生成 `(0,0) (L,0) (L,W) (0,W)`。仅当标志正好在矩形四角时使用。
- **B8 六点**：`calib_H.py` 里 B8 泳池的实测世界坐标。

### 2.5 输出文件

保存标定时写出两个文件：

1. `bird_eye_params_*.xml`：`H`、`dst_width`、`dst_height`，格式与 `find_world_pt.py` 一致。
2. 同名 `.json`：内参、畸变、去畸变方法、世界点、图像点、比例、边距，用于下次加载完整会话。

导出视频：

- 优先：ffmpeg `libx264`（CRF 18）→ 不行再试 `mpeg4`
- 再不行：OpenCV `mp4v` / `MJPG`
- 先写到系统临时目录的英文路径，完成后再移动到你选的位置（避免 Windows 中文路径导致 `[Errno 22]`）
- 同时保存一张 `*_preview.png`

### 2.6 相机 YAML 格式（可选）

与 `find_world_pt.py` 的 `camera_params.yaml` 对齐：


## 3. 和实际参考实现的差异

这里的「实际」指仓库里真正在用的两套代码：`calib_H.py`（算 H）和 `find_world_pt.py`（用 H 跑整段视频）。

### 3.1 与 `calib_H.py`

| 项目 | calib_H.py（原实现） | 本脚本 |
|---|---|---|
| 界面 | OpenCV 窗口，硬编码图片路径 | Tk 界面，可选图片/视频 |
| 输入 | 单张图 `b8_new7.png` | 视频第一帧或任意图片 |
| 去畸变 API | `fisheye.undistortImage` | 同样的 `K/D/balance`，但预计算 `initUndistortRectifyMap` 再 `remap` |
| 点选 | 先把去畸变图缩到 1/2 显示，点击后再 `×2` 还原 | 按窗口缩放显示，点击时除以 `scale_factor` 还原 |
| 世界坐标 | 写死 B8 的 6 个点 | 表格可编辑；可选矩形 4 点或 B8 六点 |
| 鸟瞰画布 | `max(x)+2.5m` 宽，`max(y)+0.5m` 高，坐标不平移 | 把最小世界坐标平移到边距处，四边都留白；宽高补偶数 |
| 透视变换 | `warpPerspective`（二次插值） | 去畸变 + H 合成一次 `remap` |
| 输出 | 只保存 XML，无视频 | XML + JSON + 整段鸟瞰视频 |
| 分辨率 | 假定输入图就是标定分辨率，不缩放 `K` | 默认按标定分辨率缩放 `K` |
| 内参 | 代码里写死；另有一组注释掉的 4K 针孔模型 | 默认同鱼眼组；可加载 YAML；针孔组已写入常量但界面需选 `standard` 并自行加载 |

相同点：默认 `K/D`、`balance=1`、`pixel_scale=100`、XML 字段名、必须先去畸变再点选。

### 3.2 与 `find_world_pt.py`

| 项目 | find_world_pt.py | 本脚本 |
|---|---|---|
| 目的 | 在已有 `H` 的鸟瞰视频上跟踪机器、算覆盖率 | 只做标定和几何矫正 |
| 去畸变 | 每帧 `undistortImage` / `undistort`，再 `warpPerspective` | 一次合成 remap |
| 相机参数 | 各泳池目录下的 `camera_params.yaml` | 默认 B8 那套；可加载 YAML |
| 视频读写 | ffmpeg 管道 rawvideo | 优先 ffmpeg 写 mp4，失败回退 OpenCV |
| 时间戳 OCR、轨迹、覆盖率 | 有 | 无 |
| XML | 读取 `bird_eye_params_{泳池}.xml` | 写出同结构 XML |

本脚本标定完得到的 XML，可以直接放到泳池配置目录，供 `find_world_pt.py` 使用。后者内部仍是「先去畸变、再 warp」，效果应接近，但会多一次插值，画质略低于本脚本导出的鸟瞰视频。

### 3.3 和物理真实世界的差异（模型局限）

这些不是实现 bug，而是模型本身做不到的事：

1. **内参必须来自这台相机。** 默认 `K/D` 是某一路鱼眼在约 2847×1612 下标定的。别的相机、别的焦距、换过镜头，池边都会去不直。缩放 `K` 只能补偿「同一相机、不同输出分辨率」，不能冒充另一台相机。
2. **单应性只对一个平面成立。** 甲板、水面、池底不共面。标志在甲板上时，水下机器人位置会有视差误差；池壁、梯子、栏杆会变形。
3. **世界坐标必须实测。** 默认 10m×8m 矩形只是占位。标志不在四角（例如右侧棋盘格在边线中部）时，必须填真实米制坐标，否则鸟瞰会长宽比错、被拉斜。
4. **点序是对应关系，不是「画面左上」。** 世界坐标的 X/Y 可以和图像行列差 90°（相机安装旋转）。只要「第 i 个世界点」对应「第 i 次点击的那块棋盘格」，`H` 就对。点错对应关系，鸟瞰会旋转或镜像。
5. **去畸变不会让所有直线完美。** 内参有标定残差，画面边缘仍可能略弯；`balance=1` 会留下黑边。
6. **时间轴上相机被认为静止。** 云台转动、风吹支架、画面被裁切后，同一套 `H` 会失效，需要重标。
7. **导出画质仍受编码限制。** 一次 remap 减少几何插值损失，但 x264/MJPG 仍是有损压缩；比例设得过低会先缩小再编码，看起来仍然糊。

## 4. 建议工作方式

1. 用**原视频第一帧**标定，不要用播放器截图。
2. 去畸变后先看池边是否变直，再点选。
3. 世界坐标用卷尺或图纸上的真实位置，单位米。
4. 点选后用「按选点自动比例」，避免固定 100 px/m 压分辨率。
5. 预览里池边仍弯：先查内参是否匹配，不要指望多点几个点能消掉鱼眼。
6. 导出失败 `[Errno 22]`：脚本已改为英文临时路径写入。若仍失败，改存 `.avi`，或安装带 `libx264` 的 ffmpeg。
